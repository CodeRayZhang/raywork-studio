# 从可运行原型到付费产品

## 第一批用户与购买理由

优先服务 2–5 人的小型内容工作室或代运营团队：同时服务多个品牌，客户经常在群里改稿，编辑花大量时间确认最终版本。

要验证的价值是“客户意见能变成明确的修改任务，少改错版本，稳定交付”，而不是承诺批量生成就能涨粉或带来收入。

## 已完成：v0.1 的最小闭环

本地工作台、品牌简报、六模块文本包、资料摘录、局部重写、版本历史、客户批注与审核、来源变更失效、ZIP 导出、任务恢复、自动化测试。真实模型适配代码可用，但真实生成质量、模型成本和付费意愿均待验证。

## 第 1 阶段：实战验证

招募 3 个团队，各选择 1 个已有客户项目，不要求迁移全部工作。先做一轮现有流程的基线记录，再用系统做两轮相近体量的交付。

| 指标              | 怎么记录                               | 继续投入的建议门槛（目标，非已达成结果） |
| ----------------- | -------------------------------------- | ---------------------------------------- |
| 人工编辑时间      | 从资料收到到可审稿，记录人工分钟数     | 相近交付量下降 30% 以上                  |
| 改错版本/遗漏意见 | 每轮逐项记录                           | 两轮无关键遗漏                           |
| 内容可用性        | 模块被直接采用、轻改、重写的比例       | 至少一半模块只需轻改                     |
| 审核体验          | 客户能否独立打开链接并完成审核         | 不依赖现场指导完成                       |
| 付费意愿          | 询问真实预算和采购人，邀请实际付费试点 | 3 个团队中至少 1 个愿意付费              |

建议试点报价可以先测试 **499 元/团队/4 周**，包含协助配置和固定范围的交付流程支持。此价格仅是假设；未开通收款，也不代表任何用户已经接受。首次真实模型测试必须记录失败调用的费用、改稿时间和最终质量，避免只展示好看的演示。

## 第 2 阶段：围绕重复出现的问题升级

1. 多品牌资料库与经过客户确认的历史稿，减少重复输入。
2. 具名审稿与团队角色，区分编辑、负责人、客户；配合稳定的 HTTPS 部署。
3. 独立任务队列、失败账单对账、调用预算和配额控制。
4. 可编辑的资料引用、多来源版本归档；让手工改稿的新增事实也有依据。
5. 项目归档、搜索、交付批次、数据导入导出和备份恢复。

仅在上述需求被真实项目证明后，再考虑订阅支付。社区版可以保持本地单工作室、用户自带 Key；托管版收费点应来自多品牌协作、稳定运行、存储和客户审核服务。

## 后续候选方向

- 客户运营周报：先支持用户上传并确认的结构化数据，所有指标带口径；不能从虚构数据生成经营结论。
- 图文成品：将已审核的文案套入确定的版式，导出可发布图片。
- 平台发布：先人工确认的发布包，再依据官方授权能力做平台连接。

以上均未实现。v0.1 不扩展成通用 Agent 平台，也不同时做获客 CRM、全自动短视频和所有社交平台运营。

## GitHub 展示策略

README 首屏放真实工作台截图和可复现的 5 分钟操作。每次发布都附变更、测试、失败边界和演示数据。取得真实团队许可后，再公开脱敏的前后对比和实际节省时间；不编造客户 logo、营收、使用量或成功案例。
