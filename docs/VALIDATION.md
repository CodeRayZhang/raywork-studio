# v0.1 验收记录

日期：2026-10-20（Asia/Shanghai）。数据为虚构品牌“山间来信”，不代表真实客户案例。

## 自动化

本地 macOS / Python 3.12：22 项 pytest 用例通过；Ruff 静态检查与格式检查通过；JavaScript 语法检查通过。

主要验证：

- 客户批注 → 局部重写 → 解决批注 → 客户确认 → 导出，整个链路实际检查 ZIP 文件与文本内容。
- 管理令牌、客户令牌隔离，客户不能访问其他项目或管理 API。
- 审稿链接过期、撤销后立即拒绝访问。
- 旧版本的修改与审核被拒绝，同时修改只接受一个版本。
- 资料变更失效；生成期间资料改变时结果不覆盖现有内容。
- 幂等请求不重复生成；失败重试、中断恢复有明确状态。
- 模拟真实 Responses HTTP 协议，验证结构化格式、用量记录、拒绝/不完整响应处理和非法引用拒绝。

本地测试依赖中的 Starlette 对 httpx TestClient 发出一条弃用提示，不影响当前测试结果。CI 配置针对 Python 3.11、3.12、3.13；远端运行结果以 GitHub Actions 为准。

## 浏览器实际操作

在本地服务中登录并载入演示项目，完成了以下操作：

1. 修改标题，并验证未保存时点击审核不会确认旧稿。
2. 创建项目审稿链接，在单独标签页进入客户视图。
3. 客户添加正文批注，正文进入待修改状态，审核按钮被阻止。
4. 工作室修改正文为 v2，保留 v1，标记意见已解决。
5. 客户确认 v2，并逐一确认全部 6 模块。
6. 下载 ZIP，读取验证 8 个文件、6 个已审核模块、正文版本 v2，文本和清单一致。
7. 验证 390px 手机与 1280px 桌面布局，无页面水平溢出；浏览器未记录脚本错误。
8. 从空白项目录入第二个虚构品牌，完成 6 模块生成和正文局部重写；新版本生成成功，其他模块保持 v1。验证手机项目切换可用。
